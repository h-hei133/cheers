# Product Architecture Reset Route Pack

This pack contains the controlling goal and the execution route documents for the product architecture reset program.

The reset program is not a feature sprint. It exists to migrate the project from a route-grown prototype toward a product-owned architecture while preserving the proof-carrying evidence model.

## Files

- `GOAL.md`: global control rules for all reset routes.
- `reset-route-a-artifact-inventory-and-index.md`
- `reset-route-b-evidence-verdict-facade.md`

- `reset-route-i-final-architecture-compatibility-audit.md`

## Execution Principle

A single `/goal` may execute multiple reset routes, but every route is a checkpoint. Each checkpoint must preserve compatibility, truthfulness, and the current Route227/228 capability distinctions.

Do not treat these routes as permission to perform broad mechanical moves. Prefer facades, adapters, indexes, aliases, and compatibility shims before physical relocation.
