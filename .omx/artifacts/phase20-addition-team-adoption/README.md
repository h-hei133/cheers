# Explicit adoption of completed team reports

Addition §17.5 requires a user's explicit adoption before a completed team report reaches the main context. Before this slice, the team tool returned the report immediately. This slice places publication in the owning team domain and reuses the existing interactive question bridge. It does not complete the whole addition or the original Phase 20 acceptance matrix.

The user sees the bounded report before choosing. The first option keeps it out; no recommendation is supplied. Publication requires a completed response with an own answer for the exact random report ID equal to `Adopt report`. Decline, empty or ambiguous input, cancellation, unavailable UI, callback errors and stale turn admission return only a safe status and report ID. No proposal, finding, verdict or evidence metadata accompanies those outcomes. A successfully adopted report retains evidence and a digest binding its content to the original session, workspace and task. Adoption grants no tool permission. Preview control characters use the existing literal display policy; reports exceeding 64 KiB in serialized or display form are refused rather than truncated for approval.

The local oh-my-pi interactive mode at 7435–7492 pauses continuation and rechecks the origin session after awaits; 7789–7833 settles caller/dialog cancellation and treats unanswered/timeout as no approval. The target reuses its existing question host and admission callback, with an independent cancellation race for hosts that ignore their signal. It does not copy the reference's separate UI infrastructure, execution-mode changes, default highlighted approval or newer `AbortSignal.any` API.
