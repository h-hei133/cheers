## 2. T1 — OAuth 凭据接线

**性质是接线，不是新功能。** 登录、刷新、凭据解析、就绪预检**四段全在且有测试**，
但请求路径只读 `apiKey`，而 account-auth 凭据没有该字段 → **每个请求发空 `Bearer `**。

**做法**：

- `provider/request/authorization.ts`：`providerAuthorization` 按凭据形态产头部，
  `api-key` → `Bearer <key>`，`account-auth` → `Bearer <accessToken>` + `chatgpt-account-id`。
  **不复用 `apiKey` 承载 token**——那会让两者不可区分，并破坏 `authMode` 的既有语义。
- `ProviderTarget.apiKey` → `headers`；`CompactionProvider` 同改（压缩路径有同一缺陷，
  只是表现为 `/compact` 报「No credential for provider」）。
- 刷新在**就绪预检之前**（预检是「凭据可用」的判断点；在一个即将过期的 token 上放行，
  会让回合在一分钟后失败而没有任何提示），**复用**既有的 `refreshOAuthTokens`/`isExpiring`，
  不自建第二套；刷新结果**写回**（否则每个请求重复交换、重启后仍从过期 token 开始）。
- 刷新失败**不致命**：保留原 token，丢弃会把可恢复的情形变成必然失败。

**验证**：`authorization.test.ts` 9 项，对着**真实 HTTP server** 断言收到的头部——
这正是原先缺的那一环（三处测试各测一段，**接缝没测**）。反向验证：还原修复 → 3 项失败。

**一处自我更正**：初稿写了 `refreshOpenAIAccountToken` 并**自己编了一个端点**，
随后发现 `core/auth/oauth/flow.ts` 已有 `refreshOAuthTokens`，改写为复用。

## 3. T2 — 技能与提示词模板展开

`/skill:demo` **修复前实机报 `Unknown slash command`**——`slashRouter.ts:12` 把它当命令名查注册表。

**两件事同一路径**（照 `pi` 的 `_expandSkillCommand` → `expandPromptTemplate` 串联）：
它们是同一类东西（「短写代表长文本」），分开实现会产生**两套分词**（引号处理必须一致）
与**两套优先级**。顺序是**技能先**：技能体可能含模板占位符，反序会先消耗掉它们。

- 技能参数**跟在体内之后**（技能是散文，作者无法预测句子落在哪），模板则**替换**（作者按参数写的）。
- 占位符照 shell 习惯：`$1`/`$@`/`${1:-x}`/`${@:2:3}`；**单遍替换**（参数里的占位符不二次展开）。
- 模板目录**与技能同一套约定**（用户级 + 项目级，项目优先），文件名即调用名。
- **路由顺序是关键**：展开**必须在未知命令分支之前**；裸名（`review auth`）走 `cliCommandExecutionBridge` 的提示词路径，两者用**同一模块**。
- 未知技能给**可用列表**（是拼错的命令）；模板缺参**留空**。`/skill <name>`（只打印）**保留**。

**验证**：实机确认 `/skill:demo` 展开、未知技能给列表、`review auth` 展开。反向验证：去掉展开 → 2 项失败。

## 4. T3 — 转录内搜索

`ctrl+shift+f` 打开粘性搜索条，**占提示行**（输入行是用户文本所在，占它等于丢掉已输入的内容）。

**匹配跑在已渲染的行上**：那是用户看到的东西，命中必有可指之处。
语料以**空格连接各行**，所以换行处的短语**能**匹配（逐行搜索会漏，而长行正是读者最容易迷失的地方），
同时**拒绝**把相邻两行当成相邻词（`foobar` 不匹配「…foo」+「bar…」）。
匹配**字面且大小写不敏感**——搜索框不是要求转义括号的地方。

`ctrl+f` **刻意不用**：它已是 emacs 式右移（`tui.editor.cursorRight`），`pi` 在有该绑定的平台上同样避开。

**两处是「表面缺失」而非「功能缺失」**：

1. **无法滚动到指定行**——pane 只能按增量或到末尾移动，两者都无法把某一行放到屏幕上，
   于是循环匹配只会更新计数器而眼前没有任何变化。新增 `scrollToContentRow`（放在**上三分之一**：
   贴底边的匹配会成为可见的最后一行，看不到它值得看的原因）。
2. **没有高亮通道**——匹配在 pane 内、**选中之后、滚动条之前**着色
   （匹配必须是滚动条所附着的行的一部分）。

**实机 PTY 验证**（决定性的）：在真实终端里打开搜索条并输入查询，渲染出
`find: alpha  ·  1/1`，匹配处以 `\x1b[7;1m`（反显+加粗）渲染。

**一处自我更正**：初稿把搜索的三个方法放进 `interactiveMode.ts`，使该模块的函数数
**23 > 20 上限**（monoliths 5 → 6）。拆出 `searchHost.ts`（键路由与滚动）与
`searchState.ts`（决策与样式），**回到 5**。这是 AGENTS.md 的职责上限，虽然是 advisory，
但前几轮一直保持 5，不该由本轮破例。

## 5. T4 — 双击选词／三击选行（含 Undo 合并）

**Undo 合并**：连续**单词字符**是一个撤销单元。这**扩展**了既有的 `lastAction` 机制
（它本就跟踪 kill/yank 的连续性），而不是新增第二套——第二套「连续」的定义必须与第一套
在移动、历史召回、粘贴上达成一致，而两套规则会分歧。空白单独成步，所以反复按撤销是**逐词**后退。

**点击粒度**：双击选词、三击选行；第四次重新开始（没有第四个含义）。
**只有同一单元格、且在时间窗内**才延续——指针移动了就是拖拽，把它算作双击会在用户选短语时选走一个词。
词**以空白为界**，所以标点粘在词上，双击 `run()` 取整个调用；点在空白上**不选**（选空隙会像手势随机失败）。
词/行选择**在拖拽中保持**（移动指针是按单位扩展，不是散回字符）。

**测试抓出的一处真缺陷**：`release` 处理器用原始释放列覆盖了 focus，
把已经拓宽到词的选择**又缩回到指针停下的位置**，于是复制出碎片。
**辅助函数一直是对的**——不把各段驱动到一起就不会发现。这也是为什么断言走 `DragSelection`
而不是只测 `spanForClick`：**正确的辅助函数不能证明它被接上了**。

## 6. T5 — `since` 游标与 `get_tree`

追加式日志的每一行早已有稳定 id，线程也早已记录它们的关系；**缺的是「询问」的方式**——
客户端能读文件，但必须知道目录布局与行格式，且必须重读整个文件才能找出没见过的东西，
**这就是「格式」与「契约」的区别**。

- **条目 id 就是游标**（写进行内；旧记录由行号派生 `line-N`），跨重启有效。
- **游标排他**：传最后处理过的 id，只得到之后的。
- **未知游标是错误而非空列表**：对同步客户端，「没有新的」与「你的游标来自别处、
  从这里开始会静默跳过中间所有」是**相反**的意思，不能共享一个答案。
- **树返回多根**：父链断裂的条目**保留为根**（静默丢弃比放错位置更糟）；
  **无 id 的条目跳过**（不能被指认的条目不能被指向）。
- `/entries` 列的是**文件**而非会话：pre-compaction 历史与被放弃的分支正是跟踪会话的客户端需要的，
  也正是消息投影会折掉的东西。

**另外**：`query.started` 新增**可选** `sessionPath`。没有它，消费者必须重建目录布局，
**那会让布局因为「不得不依赖」而事实上成为契约的一部分**。可选 → 兼容变更；没有可报告的路径时
**省略而非空串**（空串会被读成一个路径）。

**两处由「把测试写对」抓出的缺陷**：

1. **树路径崩溃**（`Cannot read properties of undefined (reading 'map')`）——快照的补录步骤读
   `session.turns`，而我传了一个只有 id 的 stub。改为经 `loadSessionRecord` 读真实记录。
2. **测试夹具只写 transcript**——那是加载器**读不出来**的会话，于是命令所有断言都因错误的原因失败。
   夹具改为**经产品同一条路径记录**（`appendSessionTurn`），turn 因此带上 transcript 的 id，游标才有真实对象可指。

**验证**：实机四种情形（全量 / 游标 / 未知游标 / 树）。反向验证：包含式游标 → 2 项失败；
容忍未知游标 → 1 项失败。

**第三处由测试抓出**：`sessionPath` 初版**无论目录是否存在都报告**——`locateExistingSessionLayout`
在目录不存在时仍返回一个路径，于是一个从未写入的会话被报告成一个**空路径**，
消费者会去一个什么都没有的地方找。改为**只报告存在的目录**，否则省略。
`cliRuntimeInvocation.test.ts` 的「synthetic prompt」用例钉住了这件事：它断言 `query.started`
**只有两个字段**，而我加了第三个——这正是「字段是可选的」这一契约的测试。
