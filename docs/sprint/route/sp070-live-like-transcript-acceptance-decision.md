# SP070 Live Like Transcript Acceptance Decision

## Goal

Validate whether current transcript recovery is strong enough to continue this project path.

This task is failed unless live-like transcript variation is recovered by product behavior through runtime harness, transcript reduction, source discovery, hypothesis repair, targeted verification, artifact proof, durable restore, evidence proof, and result verdict.

This is an acceptance and decision gate. Do not add broad new architecture unless primary trials expose a product gap.

## Required Tools

Use Serena MCP for owner discovery, references, diagnostics, and targeted edits.

Use Spec-Driven Develop for requirement coverage.

Use Superpowers where useful: using-superpowers, systematic-debugging, test-driven-development, verification-before-completion, dispatching-parallel-agents, subagent-driven-development, and code review.

Use local playbook documents first, then local mature harness source after owner inspection. Inspect only agent loop, harness, transcript reduction, tool result settlement, source discovery, repair iteration, verification rerun, artifact proof, session restore, and result reduction.

## Introduction Rule

Evaluate in order:

1. dependency use
2. structured port
3. isolated source adoption
4. behavior-only alignment

Structured port is expected for harness and transcript patterns. Isolated source adoption is allowed only for small pure reducers, transcript reducers, lifecycle transitions, safe codecs, failure classifiers, or settlement helpers after review.

Do not copy names, paths, fields, user wording, terminal truth rules, or architecture wholesale.

## Required Primary Trials

Create or update:

docs/sprint/live-like-transcript-acceptance-decision.md

Define 3 primary live-like transcript trials. They must not recycle SP044 through SP069 primary tasks.

Each trial must include:

- at least 8 phases
- at least 3 provider-like mistakes
- transcript text with false completion or generic verification claim
- real disposable workspace writes
- real failing command output
- source facts from actual reads
- hypothesis and repair plan
- targeted rerun
- evidence/result verdict or honest stopped_not_proven

Combined coverage must include:

1. over-eager write blocked or redirected to discovery
2. generic verification claim rejected before targeted rerun
3. bad repair, failed rerun, distinct next hypothesis, targeted pass
4. incomplete artifact claim, source evidence, verification evidence, proof completion
5. replay or compact restore
6. one honest stopped_not_proven chain
7. manual correction count zero

Existing diagnostics are regression only and cannot satisfy primary evidence.

## Product Fix Rule

If primary trials expose product gaps, fix rightful owners only:

- runtime harness or trajectory
- transcript or tool feedback reduction
- execution seam or dispatch
- session, replay, or compact carry-forward
- source discovery
- repair flow or planner
- verification command
- artifacts
- evidence or result only as consumers

If no product gap appears, provide a strict no-change finding with primary trial evidence. Do not mark complete from old diagnostics.

## Decision Rule

Final decision must be one of:

CONTINUE CURRENT PROJECT

Use this only if all primary trials pass, no false success is observed, not-proven behavior is honest, and validation passes.

CONTINUE AFTER ONE FIX

Use this only if exactly scoped product gaps were fixed in this task and all hard gates pass afterward.

START MIGRATION COST SPIKE

Use this if primary trials fail because current architecture cannot recover live-like transcript behavior without broad rewrite.

2. 3 primary trials execute

5. at least 3 use real failing command output
6. at least 3 perform actual writes
7. at least 2 complete after second or third hypothesis
8. at least 1 crosses replay or compact restore

18. diff checks pass
19. optional live acceptance passes if run

## Live Provider Rule

Live provider is optional.

If live is run and fails only from provider-network, provider-config, provider-auth, or provider-unreachable after non-live gates pass, set status blocked. Report retest command, expected fields, failure class, why not product failure, git status, and uncommitted state. Do not retry live repeatedly.

Live output, provider success, or catalog success cannot replace primary trial evidence.

## Naming And Safety

During development, product file names and product content must not contain process wording, comparison wording, reading-process wording, or outside project names. Use domain language only.

Evidence/result owns terminal truth. Do not claim success from provider output, tool execution, dry-run, apply, status, artifact existence, replay restore, compact summary, command output alone, transcript, trajectory entry, hypothesis, or quality counter.

Protect raw provider output, patch body, tokens, headers, secrets, private paths, and hidden reasoning. Do not manually read or print /home/wang/.private-agents-real.

Run primary live-like transcript trials before and after fixes, focused changed-owner tests, SP044 through SP069 regressions, build, truthfulness gate, anti-false-success gate, diff checks, and live only if needed.

Commit only after hard gates pass. Push once only. If push fails, do not retry.
