# 终端体验对标与视觉交互架构设计（对齐 oh-my-pi 工业级规范）

## 摘要

针对终端智能体交互系统（TUI）在实际使用中的多项核心体验痛点，本文档深度对照顶尖参考项目 `oh-my-pi`（OMP）与 `pi` 的具体工程实现，提出并规范了五大交互与视觉子系统的架构对齐方案：
1. **输入法（IME）硬件光标同步机制**：解决中文拼音悬浮窗在全屏模态框（如 Resume / Rename）中偏置于屏幕左上角的硬件游标漂移问题。
2. **终端原生滚动体系（Native Scrollback Architecture）**：剖析终端模拟器外部原生滚动条与 TUI 内部渲染机制的边界，废除污染复制与宽字符对齐的行尾填充伪滚动条。
3. **命令与输入历史持久化（Command History Persistence）**：设计基于轻量持久化日志的会话间历史记录索引，实现重启 CLI 或恢复会话后的输入框双向回溯（`Up` / `Down` 键）。
4. **剪贴板通知去重与模型忙碌静默（Clipboard Notice Governance）**：引入带标签的时间窗口通知就地更新机制，以及在模型流式响应期（`busy` 状态）的绝对静默规则。
5. **高对比度语义配色与命令盒装渲染（TrueColor Semantic Palette & Framed Command Box）**：完整提取并规范 OMP 官方标准色彩定义，杜绝模型输出污染背景色，构建带分隔线与彩色差异（Diff）的命令展开盒。

---

## 1. 输入法（IME）硬件光标同步机制

### 1.1 根因分析
在 Windows Terminal、iTerm2、WezTerm 等现代终端中，操作系统的中文/日文输入法（IME）依靠终端上报的硬件光标坐标（`CSI row;col H`）来决定拼音预输入浮层（Composition String）和候选字词框的弹窗位置。
若 TUI 全屏模态组件（如 `renderModal`、`renderRename`）仅在字符串中拼接内容而未在正在编辑的输入末尾嵌入 `CURSOR_MARKER`（`\x1b_c\x07`），渲染引擎将判定当前帧无激活焦点，执行：
```text
CSI ?25l (隐藏光标) + CSI 1;1H (硬件光标停泊在左上角)
```
导致用户输入拼音时，输入法的悬浮框出现在最左侧，而确认后的汉字却渲染在右侧标题栏内，严重撕裂输入心智。

### 1.2 对齐方案
- 在 `modal.ts` 的 `top` 标题栏过滤文本末尾以及 `overlay.ts` 的重命名输入行末尾显式嵌入 `CURSOR_MARKER`；
- 渲染管线 `cursorPaint` 自动检测并计算准确的屏幕物理行号与列号，发出精确的 `moveTo(row, col) + SHOW_CURSOR`，使 IME 候选框始终贴合正在输入的文本。

## 2. 终端原生滚动体系 vs 伪滚动条

### 2.1 架构对标
在 OMP 中，页面并未在文本右侧强行绘制字符滚动条，而是采用**标准终端原生滚动（Native Terminal Scrollback）**：
- 现代终端模拟器（Windows Terminal、Alacritty、Kitty 等）右侧自带由显卡加速的原生像素级滚动条；
- 自建字符滚动条（如使用 `│` 轨道加 `█` 滑块）必须在每行右侧强制执行 `padToWidth(row, width - 1)`。这会在行尾补入数十个多余的 ASCII 空格（`0x20`），直接导致鼠标框选复制时将大量无意义的右侧空格一并拷入剪贴板，且在中英混排（CJK 宽字符）行破坏对齐；
- 因此，终端界面的最高工程品味是**全宽纯净输出，将回滚与滚动交由终端自身负责**，或在特定局部视图中提供无损键盘滚动支持。

## 3. 命令与输入历史持久化

### 3.1 机制设计
- 在 `.ts-shell/history`（或工作区状态目录）维护纯文本命令历史文件，每行记录一条唯一或时序提交的 prompt/命令；
- 在 CLI 启动及 `/resume` 切换会话时，自动将历史记录与该会话之前的用户 prompt（`session.turns` 中 role 为 `user` 的内容）聚合，注入到 `Editor` 的内存回溯栈中；
- 确保用户退出终端后再次进入，按 `Up` 箭头能无缝浏览上一轮输入过的全部指令。

## 4. 剪贴板通知治理

### 4.1 痛点
用户使用鼠标连续拖拽复制终端文本时，每次释放鼠标都会往 Transcript 追加一行 notice，导致连续复制多次即被大量通知行刷屏；且若在模型流式生成正文时弹出，会打断阅读节奏。

### 4.2 策略
- **静默规则**：当交互表面处于 `busy` 状态（模型正在生成或工具正在执行）时，鼠标复制静默完成，不向 Transcript 写入任何提示；
- **同标签合并**：通知模块引入 `tag` 机制。10 秒内连续产生的同标签通知（如 `clipboard`），直接就地替换上一条通知块的内容，不再向账本新增条目。
