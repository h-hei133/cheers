# Risk Register

| Risk | Current evidence | Impact | Mitigation | Route |
| --- | --- | --- | --- | --- |
| CLI behavior drift | `cli.tsx` is the package executable path and `cli-baseline.test.ts` drives it through `tsx`. | User-visible startup, print, stdin, interactive, session, MCP, and provider surfaces can change accidentally. | Keep executable shim stable and run focused CLI baseline cases plus `scripts/verify-cli-entry.mjs`. | All |
| Flag parsing drift | `parseCliArgs` is delegated, but `cli.tsx` owns parse error/version/doctor branch order. | `--version`, `--doctor`, prompt derivation, project fallback, and slash prompt handling can change. | Preserve branch order; run `cliArgs.test.ts` and version/doctor baseline cases. | 1 |
| Provider default drift | Provider credential refresh closure reads runtime config and CLI overrides, and startup plan reads `PRIVATE_AGENTS_PROVIDER_MODE`. | Live provider could become accidentally enabled or hidden as synthetic. | Keep default-safe behavior, no real-provider gate, provider readiness tests, and redaction assertions. | 2 |
| Live-provider accidental enablement | Planning mutation bridge checks `PRIVATE_AGENTS_REAL_PROVIDER_SMOKE`. | A refactor could treat env presence or credentials as approval. | Preserve explicit opt-in and no live provider execution in extraction route. | 2 |
| Approval policy drift | `ApprovalTrustPolicy`, non-interactive approval, active approval mode, and audit persistence are threaded through closures. | Deny/allow-once/allow-always, trust cache, and audit memory may diverge. | Extract approval bridge with exact characterization tests and no boolean collapse. | 2, 5 |
| Approval audit redaction/shape drift | Lines 259-283 manually shape audit payload and filter `inputKey`. | Session audit memory could leak fields or lose provenance. | Preserve exact keys and add focused audit bridge tests. | 2 |
| Print vs interactive parity drift | Print/stdin/replay branches and interactive prompt execution each call runtime modules with different bundles. | Same prompt can produce different result/session/terminal surfaces by mode. | Run CLI entry parity tests for print/stdin/interactive and `verify-cli-entry`. | 3, 4 |
| Result truthfulness drift | Interactive errors suppress output only when shell state is `interrupted`; runtime invocation preserves stopped/error classifications downstream. | Interrupted, stopped, blocked, not-proven, partial, and not-run can be misreported as success. | Do not touch result classification in CLI extraction; run result-contract if moved surfaces affect output truth. | 2, 4 |
| Session command drift | Session switch refreshes MCP gateway and prompt after context changes. | Current session, `/continue`, root binding, and recovery fallback can diverge. | Keep session command facade and run session switch/current/continue baseline cases. | 4, 5 |
| Workspace root drift | Runtime base, git root, workspace root, root mode, and attach/switch all interact. | CLI can read/write against the wrong project root or hide root-binding blocks. | Keep root diagnostics exact; test workspace attach/current/switch and root-binding mismatch. | 1, 5 |
| MCP command drift | `mcpGateway` is recreated at startup and after session/workspace changes. | MCP status/tools/refresh can target stale cwd or lose unavailable-server diagnostics. | Centralize gateway lifecycle and run `cliMcpModule.test.ts`, MCP baseline cases. | 4, 5 |
| Output string drift | `cli.tsx` still contains strings for in-flight rejection, cancellation, bootstrap block, and fatal error. | Baseline/gate outputs and user guidance can regress. | Move strings with characterization tests or preserve in shim until covered. | 1, 4 |
| Import cycles | New `cli/*` owners may import entrypoint compatibility modules that already import them. | Build or runtime module loading can fail. | New owners must not import `entrypoints/cli.tsx`; compatibility facades may re-export downward only. | All |
| Deletion of compatibility paths still used | Package scripts, tests, and scripts reference `src/entrypoints/cli.tsx` and adjacent entrypoint modules. | CLI executable or tests break. | Keep entrypoint path and old facades until all consumers migrate. | 6 |
| Readline lifecycle drift | Interactive loop owns pause/resume/prompt in finally and close/SIGINT/key events. | Prompts can overlap, hang, or lose cancellation. | Extract loop in one route with pipe-spawn interactive smoke tests. | 4 |
| Double-Esc cancellation drift | Entry owns 3-second timing and messages. | Users can lose cancel affordance or cancel too easily. | Focused cancellation tests plus Ctrl+C baseline. | 4 |
| Session persistence contamination | CLI command owners receive `SessionManager`. | Extracted modules might start owning persistence details. | Keep persistence in `session/` and only pass session facade methods. | 5 |
| Doctor diagnostic drift | Doctor is currently early shortcut. | Doctor could accidentally bootstrap runtime or provider. | Keep no-provider/no-runtime doctor behavior and `cliDoctor.test.ts`. | 1 |
