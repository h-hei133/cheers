# SP071 Real Repository Development Pilot

## Goal

Prove the current autonomous harness can complete real repository style development tasks in disposable workspaces.

This task is failed unless normal QueryEngine plus execution seam performs real code discovery, multi-file edits, real command execution, debug repair, targeted rerun, artifact or source receipt proof, changed-file accounting, evidence proof, and result verdict on non-toy repository shaped tasks.

This is not another transcript fixture task, not a catalog task, not liveRun, not evaluation-only, not proof-only, not receipt-only, and not docs-only.

## Required Tools

Use Serena MCP for owner discovery, symbols, references, diagnostics, and targeted edits.

Use Spec-Driven Develop for decomposition and coverage.

Use Superpowers where useful: using-superpowers, systematic-debugging, test-driven-development, verification-before-completion, dispatching-parallel-agents, subagent-driven-development, and code review.

Use the provided playbook first, then local mature harness source after owner inspection. Inspect only agent loop, harness, session trajectory, source discovery, repair iteration, verification rerun, artifact proof, and result reduction.

## Introduction Rule

Evaluate in order:

1. dependency use
2. structured port
3. isolated source adoption
4. behavior-only alignment

Structured port is expected for harness and task execution patterns. Isolated source adoption is allowed only for small pure reducers, lifecycle transitions, safe codecs, failure classifiers, or settlement helpers after review.

Do not copy names, paths, fields, user wording, terminal truth rules, or architecture wholesale.

## Required Primary Tasks

Create or update:

docs/sprint/real-repository-development-pilot.md

Define 2 to 3 primary disposable workspace tasks. They must not recycle SP044 through SP070 primary tasks and must not be toy single-file examples.

Each task must use repository shaped code copied into a disposable workspace and must include at least:

- existing multi-file structure
- real source discovery
- real file writes
- real command output
- changed-file accounting
- targeted verification
- evidence/result verdict or honest stopped_not_proven

Combined coverage must include:

1. at least 2 primary tasks execute
2. at least 2 tasks perform multi-file actual writes
3. at least 2 tasks start with real failing command output
4. at least 1 task creates or updates a targeted test
5. at least 1 task completes after failed repair and second hypothesis
6. at least 1 task produces artifact or source receipt proof
7. at least 1 task crosses replay or compact restore
8. at least 1 task remains stopped_not_proven with exact missing proof
9. manual correction count is zero

Existing transcript and harness diagnostics are regression only and cannot satisfy primary evidence.

## Product Fix Rule

If primary tasks expose product gaps, fix rightful owners only:

- runtime harness or trajectory
- execution seam or dispatch
- session, replay, or compact carry-forward
- source discovery
- repair flow or planner
- verification command
- artifacts
- tools feedback or policy
- evidence or result only as consumers

If no product gap appears, provide a strict no-change finding with primary task evidence. Do not mark complete from old diagnostics.

## Non-Substitution Rule

If tasks do not perform real repository style development work in disposable workspaces, do not mark complete.

## Naming And Safety

During development, product file names and product content must not contain process wording, comparison wording, reading-process wording, or outside project names. Use domain language only.

Evidence/result owns terminal truth. Do not claim success from provider output, tool execution, dry-run, apply, status, artifact existence, replay restore, compact summary, command output alone, transcript, trajectory entry, hypothesis, or quality counter.

Protect raw provider output, patch body, tokens, headers, secrets, private paths, and hidden reasoning. Do not manually read or print /home/wang/.private-agents-real.
